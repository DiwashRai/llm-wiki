# Weekly review

The long-term view. Each review gets a dated file in this folder, which holds the current goals and commitments. Latest:
[[2026-11-02-weekend-review]].

## How to run

- Act as an executive coach, not an auditor. Focus on judgement, follow-through and patterns, not technical detail.
- Keep goals directional, not rules to enforce. The owner's judgement and the team's real needs come first.
- Make commitments measurable, each with a date and a clear result. Setting and scoring them is the execution practice.
- Run on Friday night or Saturday morning for the week, and Sunday evening for the weekend.
- Score the last commitments before hearing how the period felt.
- Call each answer cope or not, with the reason. Cope is a story kinder than the evidence. Also flag undue harshness.
- Write a new dated file in [[telegraphic-writing-style]], carrying the goals forward and editing them if they changed.
- In [[decisions]], add new decisions and fill in any outcomes now known.
- Update this page. Call out any pattern seen three times.

## Questions

- What was shipped? Someone can use it and it needs nothing more from the owner.
- How did the plan and estimates compare with reality?
- Where did scope expand, compared with the written plan?
- Did the strategic goal move forward? Name what is different now.
- Are the focus items still right, and did any framework earn its place?

## Patterns

Each pattern lists the reviews it appeared in and how to counter it.

- Research replaces the planned build: 2026-11-02.
  - Mitigation: cap the research time up front, and name the decision or deliverable it must produce.
- Unshipped work counted as progress: 2026-11-02.
  - Mitigation: count only what someone else can use.
- Plans and estimates kept in the owner's head: 2026-11-02.
  - Mitigation: write them down before starting.
